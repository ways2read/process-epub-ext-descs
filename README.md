# process-epub-ext-descs

A Python tool for processing EPUB 3 files to extract extended descriptions and relocate them to separate XHTML files with proper linking. This improves accessibility by allowing users to access detailed image descriptions without cluttering the main content flow.

## Features

- **Tolerant HTML parsing**: Handles noisy XHTML generated by various tools (InDesign, Pandoc, etc.)
- **Rich content preservation**: Maintains formatting, lists, tables, links, MathML, and SVG
- **Cross-nested descriptions**: Handles descriptions that span across nested sections (e.g. when headings create subsections)
- **Language detection**: Reads the `xml:lang`/`lang` attribute from each source page and applies it to generated description files
- **Heading normalization**: Optionally shifts heading levels so descriptions start at h1 (e.g. source h4/h5 become h1/h2), applied independently per description
- **Markdown headings**: Supports `#`-style heading markup within description content (e.g. `## Summary` becomes `<h2>`)
- **MathML/SVG detection**: Automatically declares `mathml` and `svg` properties in the OPF manifest when needed
- **Configurable delimiters**: Customize start/end markers for extended descriptions
- **Robust error handling**: Validates delimiter pairing and image association
- **EPUB 3 compliant**: Proper packaging with correct mimetype, compression, manifest, and spine
- **Cross-platform**: Works on Windows, macOS, and Linux
- **Comprehensive reporting**: Success, warning, and error messages

## Usage

### Basic Usage

```bash
python process_epub_ext_descs.py input.epub output.epub
```

### Custom Delimiters

```bash
python process_epub_ext_descs.py input.epub output.epub \
    --start-delim "Start of description." \
    --end-delim "End of description."
```

### Normalize Heading Levels

Shift heading levels in each description file so the highest-level heading becomes h1. For example, source headings at h4 and h5 become h1 and h2. Each description is adjusted independently. Markdown-style headings (`## Heading`) keep their explicit levels.

```bash
python process_epub_ext_descs.py input.epub output.epub --normalize-headings
```

### As a Library

```python
from process_epub_ext_descs import EPUBProcessor

# Create processor with default delimiters
processor = EPUBProcessor()

# Or with custom delimiters and heading normalization
processor = EPUBProcessor(
    start_delimiter="Extended Description Begins",
    end_delimiter="Extended Description Ends",
    normalize_headings=True,
)

# Process EPUB
success = processor.process_epub('input.epub', 'output.epub')

# Get detailed report
print(processor.get_report())
```

## How It Works

### Input Format

The tool expects extended descriptions to be marked with text delimiters in the EPUB:

```html
<div>
  <img src="images/diagram.jpg" alt="Flow diagram"/>
  
  <p>Beginning of extended description.</p>
  <p>This diagram shows...</p>
  <ul>
    <li>Key point 1</li>
    <li>Key point 2</li>
  </ul>
  <p>End of extended description.</p>
</div>
```

### Output Structure

The processor:

1. **Finds** all delimiter pairs in XHTML files
2. **Validates** that delimiters are properly paired
3. **Locates** the associated image (searching backwards through DOM)
4. **Extracts** all rich content between delimiters
5. **Creates** a new XHTML file containing:
   - A `section` wrapper with proper ID
   - The associated image marked as presentational
   - The extended description content
   - A backlink with `role="doc-backlink"`
6. **Replaces** delimiters and content with a properly-linked anchor
7. **Normalizes** heading levels so descriptions start at h1 (when `--normalize-headings` is enabled)
8. **Converts** any markdown-style headings (`#`, `##`, etc.) in content to proper XHTML headings
9. **Updates** image with `aria-details` attribute pointing to the link
10. **Updates** the OPF manifest with content properties (`mathml`, `svg`) as needed
11. **Adds** description files to the spine with `linear="no"`
12. **Repackages** the EPUB with proper compression

### Accessibility Pattern

The processor follows WCAG and EPUB Accessibility best practices:

**In the original content file:**
```html
<img id="diagram-001" 
     aria-details="anchor-extended-description-diagram-001"
     src="images/diagram.jpg" 
     alt="Flow diagram showing the water cycle"/>
<p>
  <a id="anchor-extended-description-diagram-001" 
     href="desc-diagram-001.xhtml#extended-description-diagram-001">
    Extended description
  </a>
</p>
```

**In the extended description file (desc-diagram-001.xhtml):**
```html
<?xml version="1.0" encoding="UTF-8"?>
<html xmlns="http://www.w3.org/1999/xhtml" xml:lang="en">
  <head>
    <title>Extended Description</title>
  </head>
  <body>
    <section id="extended-description-diagram-001">
      <img role="presentation" alt="" src="images/diagram.jpg"/>
      <p>This diagram illustrates the complete water cycle...</p>
      <ul>
        <li><strong>Evaporation</strong>: Water vapor rises...</li>
        <li><strong>Condensation</strong>: Water vapor forms clouds...</li>
      </ul>
      <p>
        <a role="doc-backlink" href="chapter01.xhtml#diagram-001">
          Return to content
        </a>
      </p>
    </section>
  </body>
</html>
```

**Key accessibility features:**
- ✅ Image has unique ID for backlinking
- ✅ Image uses `aria-details` to point to the extended description link
- ✅ Link has unique ID that matches the `aria-details` reference
- ✅ Extended description wrapped in `section` with ID matching link's href fragment
- ✅ Image in description file marked `role="presentation"` with `alt=""` to prevent double-announcement
- ✅ Backlink uses `role="doc-backlink"` for proper navigation semantics

## File Naming and IDs

- **IDs**: Generated from image filename + sequential counter (e.g., `diagram-001`, `photo-002`)
- **Filenames**: Prefixed with `desc-` (e.g., `desc-diagram-001.xhtml`)
- **Location**: Same directory as the source XHTML file
- **Manifest**: Added to OPF manifest with appropriate `properties` (e.g. `mathml`)
- **Spine**: Added with `linear="no"` (accessible but not in reading order)

## Error Handling

The tool validates and reports:

- ✓ **Mismatched delimiters**: Start without end, or vice versa
- ✓ **Missing images**: No image found for a description
- ✓ **Invalid structure**: End delimiter before start delimiter
- ✓ **Parse errors**: Malformed XHTML

When errors occur, the original content is left untouched and an error is logged.

## Supported HTML Patterns

The tool is tolerant of various HTML structures:

### Simple Structure
```html
<img src="image.jpg" alt="Diagram"/>
<p>Beginning of extended description.</p>
<p>Description content...</p>
<p>End of extended description.</p>
```

### Nested Structure (e.g., InDesign output)
```html
<div class="wrapper">
  <div class="inner-wrapper">
    <div class="image-container">
      <img src="image.jpg" alt="Diagram"/>
    </div>
  </div>
</div>
<p>Beginning of extended description.</p>
<p>Description content...</p>
<p>End of extended description.</p>
```

### Figure Element
```html
<figure>
  <img src="image.jpg" alt="Diagram"/>
  <figcaption>Figure 1</figcaption>
</figure>
<p>Beginning of extended description.</p>
<p>Description content...</p>
<p>End of extended description.</p>
```

## Markdown Headings in Descriptions

When writing extended descriptions in the source EPUB, you can use markdown-style heading markup inside `<p>` elements. The processor will convert these to proper XHTML headings in the generated description files.

| Markup | Result |
|--------|--------|
| `# Title` | `<h1>Title</h1>` |
| `## Section` | `<h2>Section</h2>` |
| `### Subsection` | `<h3>Subsection</h3>` |
| `#### Detail` | `<h4>Detail</h4>` |
| `##### Fine detail` | `<h5>Fine detail</h5>` |
| `###### Finest` | `<h6>Finest</h6>` |

Inline formatting is preserved: `<p>## <b>Bold Heading</b></p>` becomes `<h2><b>Bold Heading</b></h2>`.

## Limitations

- Delimiters must be in plain text paragraphs (`<p>` elements)
- Only searches backwards from delimiter to find image
- Delimiter text must match exactly (case-sensitive)

## EPUB Compliance

The tool ensures:
- `mimetype` file is first and uncompressed
- All other files are compressed with DEFLATE
- OPF manifest is properly updated
- XHTML files use proper XML namespaces
- Extended description files are valid XHTML

## Troubleshooting

### No images found
- Verify images are actually in the XHTML before the delimiters
- Check that image paths are correct in the source
- Ensure images are within reasonable proximity (same section)

### Delimiters not recognized
- Verify exact text match (including punctuation and capitalization)
- Ensure delimiters are in `<p>` elements, not other tags
- Check for extra whitespace or hidden characters

### EPUB won't open after processing
- Validate the input EPUB first
- Check error messages in the report
- Verify all file paths are correct in the OPF
